能力 · CAPABILITIES

不止回答，
而是做完。

从一句需求到一份可合并的改动，中间所有繁琐的步骤，都交给它。

01

对话即需求

用日常语言说目标，它负责把模糊的想法整理成可执行的任务。

02

自主拆解

阅读仓库上下文，定位改动点，自己决定下一步，而不是把选择题丢回给你。

03

真实代码库

在独立分支上工作，沿用项目已有的结构与风格，不制造第二套规范。

04

自动化验证

改完先运行检查。结构与链接、桌面与移动端，能验证的都不靠口头保证。

05

标准 PR 交付

每个变更都是一个完整的 Pull Request：改了什么、为什么改、验证结果都写清楚。

06

人类把关

它从不替你按下合并。评审、提问、修改，节奏由你掌握。

常见问题 · FAQ

你可能
想知道。

关于能力边界与工作方式，先把话说清楚。

SuperAgent 现在处于什么阶段？

目前是原型阶段（Beta），专注于边界清晰的小型任务：官网与页面、文档、脚本、组件和小修复。能力范围会随着真实的交付记录逐步扩大。

它会在哪些地方接需求？

飞书对话，以及 GitHub Issue。把仓库位置、想改的页面或功能说清楚即可；如果有参考链接或截图，一并附上会更好。

它会不会直接合并我的代码？

不会。它只负责打开 Pull Request；评审、修改意见和最终的合并都由人完成。任何改动都可以在合并前回滚。

代码和数据安全吗？

它在你的仓库与授权范围内工作，只读取完成任务所需的上下文。私有仓库的内容不会被发布到公开渠道。

我该怎么开始？

在 GitHub Issue 里 @miracleguy2，或在飞书里直接描述需求。第一次任务建议从小而明确的目标开始，例如“把这个页面的标题改一下”。
